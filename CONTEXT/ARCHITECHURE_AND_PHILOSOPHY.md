# Vault Tracker Context Master

Purpose:

Preserve all architectural, coaching, and philosophical decisions behind the project.

This document is intended for:

- Future AI assistants
- Future developers
- Project continuity

---

# Core Philosophy

Planner determines:

WHEN training occurs.

Program determines:

WHAT training occurs.

Progress determines:

WHAT ACTUALLY HAPPENED.

This distinction is non-negotiable.

---

# Athlete Type

Primary Audience:

- Competitive high school vaulters
- College vaulters
- Serious club athletes

Not intended for casual fitness users.

---

# Coaching Philosophy

The application should reflect how real pole vault programs operate.

The athlete's schedule changes frequently due to:

- Weather
- Meets
- Travel
- Recovery
- Facility access

The system must be flexible while preserving training intent.

---

# Why The Weekly Planner Exists

Traditional training apps force a schedule.

Pole vault coaches rarely operate that way.

Instead:

Coach defines:

- Required vault sessions
- Required strength sessions
- Required speed sessions

Athlete determines:

When those sessions occur.

The planner was built specifically to solve this problem.

---

# Traffic Light Philosophy

Traffic lights are guidance.

Not restrictions.

The app should help athletes avoid poor scheduling decisions.

The app should not prevent them.

---

# Speed Philosophy

Training allocation:

65% Acceleration

25% Maximum Velocity

10% Runway Specific

Acceleration remains the highest priority.

Reason:

Acceleration transfers directly into vault runway performance.

---

# Vault Philosophy

Vault sessions are categorized by training type.

Categories:

VD1 Drill Day

VD2 Technical Day

VD3 Short Run Day

VD4 Competition Day

VD5 Long Run Day

These categories are sufficient.

The app does not need detailed technical coaching instructions.

The athlete or coach already understands the purpose of each session.

---

# Strength Philosophy

Strength progression:

Rebuild:
General strength

Build:
Strength + power

Specific:
Power + vault transfer

The app should gradually shift from traditional lifting toward explosive work.

Approximate progression:

Rebuild:
80/20

Build:
70/30

Specific:
50/50

Traditional → Explosive

# Non-Negotiable Rules

Always return full files.

Never return code snippets.

Generated schedules are phase-aware.

Targets are phase-driven.

Targets are never hardcoded.

Training catalogs drive workout generation.

Progress calendar remains historical.

Weekly planner remains future-facing.

Planner and Progress must never become the same feature.
